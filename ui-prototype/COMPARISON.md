# KIKUtab 現在版とUIプロトタイプの比較

## 1. 比較の前提

このプロトタイプは、本番版を置き換える完成実装ではありません。

比較対象は、次の短い利用目的です。

```text
TAB譜のリズムが分からない
→ 必要な1〜2小節だけ入力
→ 再生
→ リズムを理解する
```

評価の中心は機能数ではなく、「入力から再生まで迷わず進めるか」です。

## 2. 現在版との比較

| 評価項目 | 現在版 | プロトタイプ | 評価 |
|---|---|---|---|
| TAB入力完了までの操作数 | 入力・編集を開き、音価選択後にTAB入力へ進む | 1桁フレットなら音価、弦、数字、決定の基本4操作 | プロトタイプが短い |
| 縦スクロール量 | 譜面、音価、TAB入力、再生が縦に並ぶ | 譜面と再生を上部にまとめ、現在の入力だけ表示 | プロトタイプが少ない |
| 譜面が見えなくなる時間 | stickyで改善済みだが、入力UIやキーボードとの組み合わせに注意が必要 | 譜面を上部に維持し、ネイティブキーボードを開かない | プロトタイプが安定しやすい |
| 次に何をするか | 機能を自由に選べる一方、初見では選択肢が多い | 3段階の現在位置と次の説明を常に表示 | プロトタイプが明確 |
| 音符の意味・拍数 | 大きなカードで分かりやすい | コンパクト化しても名称と拍数を同時表示 | 強みを維持 |
| スマホでの押しやすさ | タップ領域を考慮済み | 弦、数字キー、再生を44px以上で設計 | 同等以上を目標 |
| 画面上の情報量 | 既存機能が同じ画面内に多く見える | 現在の操作以外を非表示 | プロトタイプが少ない |
| 再生までの速さ | 全機能を扱える | 最短フローに絞っている | プロトタイプが速い |
| KIKUtabらしさ | 教育的な音価表示と順次入力 | 同じ強みを残し、順番をさらに見える化 | 維持できている |
| 高機能ソフト化の回避 | 本格記譜より軽量 | 1〜2小節、3ステップ、必要操作だけ | 方向性に合う |

操作数は1桁フレットの音符を1つ入力する場合の目安です。現在版とプロトタイプでは内部機能の完成度が異なるため、厳密な速度比較は実機テストで行う必要があります。

## 3. 取り入れた設計思想

### Soundslice

- 譜面を画面の主役にした
- 選択中の音を譜面と入力パネルの両方で明示した
- Undo、Redo、Deleteを選択・入力位置の近くへ置いた
- よく使う操作を表に出し、不要な操作を現在ステップから隠した

### Flat

- スマートフォンでは譜面を中央・上部へ維持した
- 入力操作を譜面の下へ集約した
- PCでは同じ機能を左右配置へ変えた

### Songsterr

- 再生位置を赤い縦カーソルで表示した
- 現在再生中の音も別の背景色で示した
- 再生操作を1行へまとめた

### Chordify

- 再生、先頭、ループ、速度を短いラベルでまとめた
- 初心者が最初に必要としない情報を増やさなかった
- 現在の操作を文章で短く案内した

### MuseScore

- 譜面上の音を選んだとき、その音に関係する操作だけを表示した
- 大量のツールバー、パレット、設定項目は採用しなかった

## 4. 意図的に残したKIKUtab独自の強み

### 音価と拍数を同時に表示

音符記号だけにせず、次を常に表示しています。

- 4分音符：1拍
- 8分音符：1/2拍
- 16分音符：1/4拍

### 順番に入力すれば使える

```text
音の長さ
→ 弦
→ フレット
→ 決定
```

ユーザーが操作方法を推測しなくても進める構造を維持しています。

### 弦を直接選択

フレットボードは採用せず、1〜6弦を大きなボタンから直接選べます。

### 1〜2小節へ限定

8拍を超える入力を受け付けず、長大な譜面制作UIへ広げていません。

### ログインなしですぐ入力

起動後すぐSTEP 1を表示し、ライブラリやアカウント画面を追加していません。

### スマートフォンで押しやすい

見た目はコンパクトにしつつ、主要ボタンは44px以上を維持しています。

## 5. プロトタイプで試した改善

### 文脈別入力パネル

その瞬間に必要な操作だけを表示します。

- 音価選択中：音符／休符と音価
- 弦選択中：6本の弦
- フレット入力中：選択中の弦、数字キー、決定
- 既存音選択中：TAB変更、削除

### アプリ内フレットキー

iPhone・Androidのネイティブキーボードを開かず、0〜24を入力できます。

これにより、キーボード表示による画面移動、sticky再描画、入力欄の隠れをUI構造から減らせます。

### 選択と再生の可視化

- 選択中：青い枠と薄い青背景
- 再生中：薄い赤背景
- 現在位置：赤い縦カーソル

色だけに頼らず、枠とカーソルも併用しています。

## 6. 本番へ採用する場合の提案

### そのまま採用推奨

- 3段階の入力ステップ表示
- その瞬間に必要なUIだけを表示する考え方
- コンパクトな1行再生バー
- 選択中の音を譜面と入力パネルの両方で明示
- 譜面上の再生カーソル
- 880px譜面と譜面部分だけの横スクロール
- PCで譜面と入力を左右に分ける考え方

### 要調整

- アプリ内フレットキーの数字配置と高さ
- スマートフォンでstickyにする範囲と占有高さ
- 既存音をタップした後の編集項目
- 速度ボタンの切り替え方法
- 再生カーソルの色・太さ・追従スクロール
- 休符追加後に選択状態を残すか
- 付点、タイ、スラー、連符をどのタイミングで表示するか

### 採用しない方がよい

- プロトタイプの簡易譜面描画を本番のVexFlow描画と置き換えること
- プロトタイプの簡易音声を本番再生処理と置き換えること
- 既存の保存・移行処理をプロトタイプの簡易状態管理へ置き換えること
- 全機能を3ステップへ無理に詰め込むこと
- 付点、タイ、スラー、連符を削除すること
- スマートフォンとPCを完全に同じ配置へ固定すること

## 7. 本番採用前に必要な検証

1. iPhone実機で譜面、再生バー、数字キーが同時に操作できるか
2. Android実機で同じ操作を確認
3. 320px、390px、430px幅で押しやすさを比較
4. 短い横画面でstickyを解除した方が使いやすいか
5. 初見ユーザー5人程度が説明なしで再生まで進めるか
6. 現在版とプロトタイプで入力完了時間を計測
7. 付点、タイ、スラー、3連符、5連符を文脈UIへ追加しても複雑にならないか

## 8. 結論

プロトタイプの方向性は、KIKUtabを高機能化するのではなく、既存の入力手順を短く見せるものです。

本番へ最初に採用する候補は、次の4点です。

1. 現在ステップだけを表示
2. コンパクトな再生バー
3. 選択中・再生中の位置を明確化
4. ネイティブキーボードを使わないフレット入力

本番へ直接移植する前に、現在版とプロトタイプを実機で触り比べ、入力時間と迷いの少なさを確認するのが安全です。
